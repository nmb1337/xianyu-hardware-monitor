# 闲鱼硬件低价监控

本地运行的闲鱼电脑及硬件价格监控工具。为每个关键词设置最低价和最高价，首次扫描建立已有商品基线；之后发现价格处于区间内的新商品时，通过 AstrBot 和 NapCat 向指定 QQ 私聊发送提醒。

支持笔记本、台式整机、CPU、主板、显卡、内存、硬盘/SSD、显示器、电源、机箱、散热器、网卡和自定义品类。

本项目不提供客服、会话管理或买家自动回复功能；AI 仅用于低价商品审核。升级不会删除已有监控规则、登录资料或提醒配置；旧版本的客服数据如已存在，会保留在本地但不再读取或使用。

## 功能一览

### 监控规则
- 13 个品类：笔记本、台式整机、CPU、主板、显卡、内存、硬盘 / SSD、显示器、电源、机箱、散热器、网卡、自定义。
- 每条规则包含：名称、闲鱼搜索词、最低价与最高价（提醒区间）、必须包含词、排除词、仅个人卖家、启用开关。
- 支持添加、编辑、停用 / 启用、删除；表格显示查询顺序（按顺序第 N 位）、上次结果时间与最近一次错误。
- 任意规则可点“扫描”立即执行一次，不必等待轮询顺序。
- 修改规则的关键词或筛选条件会清空该规则基线，下次扫描重新建立。

### 扫描与调度
- 启动监控后按规则创建顺序循环查询：完成一条立即查下一条，最后一条之后从头开始。
- 同一时间只访问一个搜索页（串行执行）；扫描之间不设间隔、每小时次数上限或夜间静默。
- 每次扫描汇报：低价匹配数、已见未提醒数、新增提醒数、屏蔽数，以及 AI 过滤与屏蔽数。
- 搜索使用“新发布”排序并读取“最新”结果接口，单次最多处理 30 个搜索结果。
- 状态栏实时显示：监控状态、当前规则、下一条规则、访问暂停与恢复进度提示。

### 基线机制
- 规则首次扫描只建立基线：记录当时已存在的商品，不发送提醒。
- 之后新出现且价格处于区间内的商品提醒一次；同一商品不重复提醒，已有商品降价也不会被当成新发布重复提醒。
- 改规则会重建基线；删除规则会同时清理该规则的商品基线与提醒记录。

### QQ 提醒（AstrBot + NapCat）
- 通过 AstrBot 的 IM 接口，用 NapCat 登录的 QQ 向接收 QQ 发送私聊提醒；消息含“品类 | 规则”、商品标题、价格、提醒区间与商品原链接（单条消息截断到 1500 字符）。
- 提醒队列持久化：发送失败自动重试，最多尝试 6 次、等待时间指数退避（20 秒起，单次上限 20 分钟）；“重试失败消息”可一键重新入队。
- 程序重启后自动恢复“发送中”的消息；相邻两条消息至少间隔 4 秒；队列每 2 秒处理一次，每轮扫描结束后也会立即处理。
- 登录恢复、访问验证暂停、需要人工处理等状态变化会额外发送一次 QQ 通知。
- 页面“提醒记录”显示最近 8 条与状态（pending / sending / sent / failed / blocked）。

### 访问验证与浏览器恢复
- 自动检测 Chrome 与 Edge；可用 `.env` 的 `XIANYU_BROWSER_PATH` 指定，两个浏览器使用独立资料目录（`data/chrome-profile`、`data/edge-profile`），互不复制 Cookie。
- 登录与验证检测覆盖：登录 Cookie、页面文案、验证弹层遮罩、搜索接口返回码（RGV587、USER_VALIDATE、SESSION_EXPIRED 等）与 HTTP 401/403/429。
- 遇到访问验证或登录失效：自动暂停 → 关闭监控浏览器 → 自动切换到另一种浏览器 → 打开并确认缓存登录 → 自动继续查询，全程无需点击按钮。
- 连续两次自动恢复仍未成功会停止自动切换（避免反复开关窗口），并通过页面与 QQ 提示人工完成；之后程序确认有效即自动恢复自动模式。
- 手动按钮：打开登录、重新登录、切换浏览器、验证登录、恢复扫描、关闭浏览器；手动关闭的窗口不会自动重开。
- 不会自动填写密码、处理验证码或绕过平台限制；检查登录只读本地页面与 Cookie。

### 低价商品与屏蔽
- “低价商品”表显示已提醒商品、提醒价区间、发现时间与原链接。
- 屏蔽商品：立即取消其待发提醒，之后不再显示或提醒；超长标题也完整保存（受 128 KB 请求体上限约束）。
- “已屏蔽商品”显示屏蔽原因与时间，可恢复；恢复后商品重新显示，因屏蔽取消的提醒继续发送。
- 手动恢复过的商品会被 AI 豁免，不再被 AI 自动过滤或屏蔽。

### AI 智能筛选
- 可选启用，兼容任何 OpenAI 格式接口（Ollama、中转服务均可），支持“测试 AI”验证连通性。
- 仅审核通过规则筛选的新商品（基线不审核），用于过滤配件、维修件、跑题标题等误报。
- 支持两种结果：`notify=false` 只过滤提醒并记录理由；`block=true` 自动屏蔽（需要明确故障 / 魔改、置信度 ≥ 0.9，且证据必须逐字出现在商品信息里，否定描述不算缺陷）。
- 每批最多 10 条、每次最多 30 条，输出上限随批量调整；单批失败不影响其他批次与基础提醒；每个请求 60 秒超时。
- 兼容 JSON 模式回退、前后文容错、错误信息脱敏（不回显 API Key）。
- 停止监控、关闭浏览器或关闭 AI 开关会取消等待中的请求；未保存的编辑不会被自动刷新覆盖。
- “AI 未通过商品”保存最近 100 条记录（理由、原文依据、处理方式、时间），支持“恢复提醒”撤销误判。

### 界面与数据
- 本地中文控制台：状态概览、闲鱼浏览器、监控规则、QQ 提醒、AI 智能筛选、提醒记录、低价商品、AI 未通过商品、已屏蔽商品。
- 数据保存在 `data/monitor.sqlite`（WAL 模式）；网页每 5 秒自动刷新。
- 仅监听 `127.0.0.1`；已保存的 Key 不在页面回显；请求体上限 128 KB。
- 升级自动迁移：保留规则、基线、屏蔽与提醒记录，清理旧版本的间隔 / 冷却 / 客服等废弃状态。

### 部署
- `pnpm start` 或 `start.ps1`（自动使用项目捆绑的 Node，缺依赖时自动安装）；`PORT` 可改端口。
- Windows 任务计划开机自启，完整步骤见 [Windows 11 部署说明](docs/WINDOWS11_DEPLOY.md)。

## 启动

需要 Node.js 22.13 或更高版本，并安装 Google Chrome 或 Microsoft Edge。

```powershell
pnpm install
pnpm start
```

打开 `http://127.0.0.1:8788`（可用 `PORT` 环境变量改端口）。

也可以直接运行 `.\start.ps1`：它会优先使用项目内捆绑的 Node，缺少依赖时自动执行安装，然后启动服务。

第一次使用时，在“闲鱼浏览器”中打开登录窗口并完成登录，然后验证登录状态。浏览器用户数据、SQLite 数据库和 AstrBot API Key 保存在 `data/`，该目录已被 Git 忽略。

默认优先使用 Chrome，也可在项目根目录的 `.env` 中指定 Edge，重启服务后生效：

```text
XIANYU_BROWSER_PATH=C:\Program Files (x86)\Microsoft\Edge\Application\msedge.exe
```

路径必须指向已安装的浏览器，配置无效时不会悄悄切回 Chrome。页面状态栏显示实际选用的浏览器。Chrome 继续使用 `data/chrome-profile`，Edge 单独使用 `data/edge-profile`，首次切换需要在新窗口手动登录；以后复用各自的登录资料，不复制 Cookie，也不删除旧资料。遇到访问验证或登录失效时，程序会自动改用另一种浏览器尝试恢复。

监控打开的浏览器使用 Windows 系统默认的网络设置，程序不额外配置代理。

## AstrBot + NapCat

1. 安装 AstrBot 和 NapCat，并在 NapCat 登录用于发消息的 QQ。
2. 在 AstrBot WebUI 的“机器人”中创建并启用 `OneBot v11` 机器人。记下其 ID，例如 `napcat-qq`。
3. 在 AstrBot OneBot 设置中使用反向 WebSocket 端口 `6199`；在 NapCat 的网络配置创建“WebSocket 客户端”，地址填写 `ws://127.0.0.1:6199/ws`。AstrBot 日志显示 OneBot 适配器已连接后再继续。
4. 在 AstrBot WebUI 的“设置”创建开发者 API Key，仅勾选 `im` 权限。
5. 在本工具的“QQ 提醒”中填写 AstrBot 地址（默认 `http://127.0.0.1:6185`）、IM API Key、OneBot 机器人 ID 与接收 QQ 号，然后点击“发送测试”。

提醒由 NapCat 已登录的 QQ 发出，接收 QQ 是你的收件账号；两者不是同一个概念。通常需要让机器人 QQ 与接收 QQ 互为好友。QQ 消息和本地控制台都会包含商品原链接。

## 可选 AI 二次审核

控制台中的“AI 智能筛选”支持 OpenAI 兼容接口。它只审核已经通过关键词、卖家和价格规则的**新低价商品**，用于减少配件、维修件、标题党等误提醒；不会访问闲鱼、处理验证码或自动回复买家。AI 请求失败时默认保留基础规则结果，不会因为模型故障漏掉提醒。

本地模型可使用 Ollama 的 OpenAI 兼容接口：

```text
接口地址：http://127.0.0.1:11434/v1
API Key：留空
模型名称：qwen2.5:7b
```

也可以填写其他 OpenAI 兼容服务的地址、API Key 和模型名。启用前先点击“测试 AI”；模型只会收到商品标题（描述可能为空）、价格、卖家名、商品 ID 和当前规则信息，不会收到登录资料。如需附加自己的筛选要求，可向本地数据库 `settings` 表写入 `ai_review_prompt`，它会并入系统提示。

AI 请求不强制指定 `temperature`，使用模型默认采样设置，避免不支持该参数的中转模型返回 400。接口明确不支持 JSON 模式（或未提供具体错误）时，最多重试一次并移除 `response_format`。失败时页面显示状态码及接口提供的错误原因，密钥会脱敏；不会因模型、密钥或额度错误而反复重试。模型在 JSON 前后多余的文字会被容错提取。

每次扫描最多送审 30 个新商品，按每批 10 条拆分请求，并按批量大小调整输出上限，避免回应过长被截断。每个请求有 60 秒超时，即使中转服务卡住也不会拖住后续扫描。单批失败只影响那一批：失败或漏回的商品按基础规则照常提醒，其他批次的审核结果仍然生效；状态栏会明确区分“审核失败”与“审核部分失败”。

“启用 AI 低价商品审核”勾选后立即保存，取消勾选会关闭后续审核并取消正在等待的 AI 请求，不需要再点保存。停止监控或关闭闲鱼浏览器也会取消等待中的 AI 请求。取消审核后保留基础规则匹配结果；已屏蔽商品及审核记录不受影响。接口地址、模型、密钥仍通过“保存 AI 设置”保存，未保存的编辑不会被页面自动刷新覆盖。

“AI 未通过商品”显示最近 100 条未通过记录，包括商品、价格、所属规则、具体理由、原文依据、处理方式与审核时间。“仅过滤提醒”与“已屏蔽”分开显示，解除屏蔽后会显示“已解除屏蔽”。记录保存在本地数据库，重启后仍可查看；AI 未返回理由时明确标记“AI 未提供具体理由”。旧版本未保存的过滤理由无法补回，首次基线扫描也不会进行 AI 审核。

“恢复提醒”可撤销误判：删除该条审核结果（以及 AI 自动加的屏蔽）后，下次扫描会把它当新商品重新判断并照常提醒；之后 AI 不会再自动过滤或屏蔽这个商品。同样，在“已屏蔽商品”中手动恢复的商品也会获得这一豁免，不会被 AI 重新屏蔽。

## 访问验证与自动切换

- 搜索遇到访问验证或登录失效时，暂停自动查询、关闭本项目管理的闲鱼浏览器，并通过 QQ 提醒一次。不会关闭你其他浏览器窗口，也不会删除登录资料、规则或商品记录。
- 监控运行时，程序会立即自动切换到已安装的另一种浏览器（Chrome 与 Edge 互为备用，各自使用独立资料目录），打开窗口并检查缓存登录；缓存有效且页面没有验证时自动解除暂停，继续按规则顺序查询，不需要点击任何按钮。
- 如果打开的窗口尚未登录，请人工完成登录或验证；完成后程序会自动确认并继续查询，也不需要点击“恢复扫描”。检查过程只读取本地页面和 Cookie，不会为检查状态而反复刷新搜索页。
- 连续两次自动恢复窗口后搜索仍提示访问验证（例如两个浏览器都被要求验证）时，程序会停止自动切换窗口，避免反复开关；页面和 QQ 会提示点击“打开登录”人工完成，之后程序确认有效时仍会自动继续。
- “重新登录”可手动执行“关闭旧窗口 → 打开登录窗口”；手动关闭浏览器窗口后不会自动重开，需要时点击“打开登录”。
- “切换浏览器”可随时手动切换到另一种浏览器；自动与手动切换都不会复制 Cookie、不会自动填写密码，也不会自动处理验证码。
- 这是一套会话恢复流程，不保证重新登录后平台不再要求验证，也不绕过验证码、登录验证或平台访问限制。

## 运行行为

- 启动监控后，程序按规则创建顺序逐条查询：每完成一条规则马上查下一条，到最后一条后从头循环，不设间隔、每小时次数上限和夜间静默。
- 首次扫描只建立基线，不提醒扫描开始前已经存在的商品；之后新出现的商品价格处于设定区间时提醒一次。
- 同一商品不会重复提醒；已有商品后续降价不会被当成新发布商品提醒。
- 修改关键词、价格区间或筛选条件会清除该规则旧基线，并在下次扫描重新建立基线。
- 程序串行执行扫描，同一时间只访问一个搜索页；每次扫描都包含页面加载、排序点击等多个网页请求，不等于只有一个 HTTP 请求。
- 连续高频访问更容易触发平台验证；不保证平台允许长期持续访问，也不绕过验证码、登录验证或平台访问限制。
- 旧版本的低频/持续模式、全局间隔、每小时上限、夜间静默、规则最短间隔和验证冷却已移除。升级后不会重置商品基线、规则、屏蔽商品和提醒记录；这些只影响搜索频率的设置也从规则表单和界面中删去。

## 测试

```powershell
pnpm test
```

当前共 107 个测试用例，覆盖商品过滤、数据库与迁移、HTTP 接口、监控调度、AI 审核（分批、超时、证据校验、恢复提醒）、QQ 提醒队列、浏览器会话恢复与仪表盘渲染。

浏览器回归测试使用临时浏览器和本地模拟响应，不访问闲鱼，也不读取 `data/` 登录资料；未安装 Chrome 或 Edge 时会跳过这些测试。

## 屏蔽商品

低价商品表中点击“屏蔽”后，该闲鱼商品 ID 会被持久化过滤：不再显示、不再入队提醒；已有的待发提醒会取消。支持超过 500 字的长标题，并保留完整原文。可在“已屏蔽商品”中恢复，恢复后商品重新显示，因屏蔽取消的待发提醒会继续发送；手动恢复过的商品不再被 AI 自动过滤或屏蔽。

## 本地 HTTP 接口

控制台使用的接口都监听在 `127.0.0.1`，供页面调用，也可用于脚本化：

- 状态与规则：`GET /api/status`、`GET /api/categories`、`GET /api/rules`、`POST /api/rules`、`PUT /api/rules/:id`、`DELETE /api/rules/:id`、`POST /api/rules/:id/scan`
- 监控控制：`POST /api/monitor/start`、`POST /api/monitor/stop`、`POST /api/monitor/resume`
- 浏览器：`GET /api/browser`、`POST /api/browser/login`、`POST /api/browser/restart-login`、`POST /api/browser/switch`、`POST /api/browser/verify`、`POST /api/browser/close`
- 商品与提醒：`GET /api/listings`、`GET /api/blocked-listings`、`POST /api/blocked-listings`、`DELETE /api/blocked-listings/:itemId`、`GET /api/notifications`、`POST /api/notifications/retry-failed`
- AI：`GET /api/ai-rejections`、`POST /api/ai-rejections/:itemId/restore`
- 设置：`GET /api/settings`、`PUT /api/settings`、`POST /api/settings/test-astrbot`、`POST /api/settings/test-ai`
